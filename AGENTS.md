# FITDLE — Agent & Maintainer Notes

This file is the engineering/AI handoff. Human-facing introduction and hosting
instructions live in [README.md](README.md).

## Non-negotiable rules

- Never reveal today's target ship, killmail ID, victim name, or answer render in
  tests, logs, commits, screenshots, or chat. Use non-target/public data in screenshots.
- Do not bump the version or add `CHANGELOG.md` entries for ordinary changes.
  Bump only when the user explicitly asks for a release/version change.
- Do not commit `.cache/`, `dist/`, browser state, or the GitLab token.
- Keep the puzzle deterministic for every player: fixed date seed, stable hull /
  page hashes, and page-1-first zKill selection.
- Do not add a backend, account system, or runtime database. The game is static.
- Prefer official SDE/zKill/ESI/image sources. Do not cache images in the repo.
- Do not hard-code deployment domains in authored JS/CSS/HTML. Use `manifest.links`
  or runtime location; share OG images may use build-time `SITE_URL`/`CI_PAGES_URL`.

## Architecture

- Pure static ES modules; no bundler. `dist/` is assembled by
  `scripts/build-dist.mjs`.
- Build-time catalog + runtime zKill/ESI. The answer is a victim hull from a
  specific live killmail.
- `data/manifest.json` is generated by `scripts/build-catalog.mjs`; it contains
  pools, links, data version, SDE build, zKill snapshot, version.
- `data/catalog.json`, `data/refs/*.json`, `data/killpool.json` are generated.
- `dist/` contains authored `js/`, `styles/`, `assets/`, generated `data/`,
  `vendor/dogma-engine/`, and static share pages.

### Boot flavor

- Authored file: `assets/boot-flavor.json` (not generated, not in `data/`).
- Normal subtitle pools per locale plus tagged eggs (`en`, `ja`, `zh`).
- Each load picks one normal line; with a 5% chance it picks an egg whose
  `lang` matches the active interface locale.
- The main boot title and the localized scanning status stay fixed.

### Hidden watchlist

- Authored file: `assets/watchlist.json` (not generated, not in `data/`); ships empty.
- Arrays: `characters`, `corporations`, `alliances`; numeric IDs or numeric strings.
- When the current victim matches any watched character/corporation/alliance ID,
  every revealed victim avatar gets an animated rainbow glow.
- Do not expose the list or its match state in the UI, metadata, share pages, or
  any public text. The effect appears only after the puzzle is revealed.

### Main modules

- `js/main.js` — boot, target/KB resolution, rendering, radar, free mode,
  language/mode, sharing, modals, footer.
- `js/game.js` — date/downtime helpers, deterministic target picking, state,
  stats, share URL, result grid.
- `js/clues.js` — SDE clue construction, profile matching, equipment weights,
  abyss base-value weights, module size weighting.
- `js/reveal.js` — weighted initial reveals, normal equipment budget, abyss
  reveal cadence, matching reveals, mix rule.
- `js/i18n.js` — 8 locales, legal copy, manual copy; all zh variants → `zh`.
- `js/dogma.js` / `vendor/dogma-engine` — abyss all-V simulation.
- `scripts/*` — SDE, killpool, ship weights, dogma, catalog, dist, version hooks.

## Data flow

1. `prepare:sde` downloads/extracts the official JSONL SDE and normalizes it.
2. `build:killpool` builds a small offline fallback pool from zKill global losses
   and stores zKill's server `Date` as `serverDate`.
3. `build:weights` fetches zKill `stats/shipTypeID/{id}/kills/` for all SDE hulls
   and stores recent/all ship-loss counts in `.cache/ship-weights.json`.
   zKill's `rankings.recent` bucket is a 90-day window; the internal `losses30`
   clue key is legacy, and the UI must label it as 90 days.
4. `build` reads normalized SDE + weights + killpool and writes `data/` and
   `dist/`.
5. Runtime: build a weighted hull candidate list, fetch page 1 for each hull,
   pick a baseline/fallback pair, then fetch the chosen killmail live.

## Target selection

- Eligibility: all SDE hulls except those with zero all-time zKill losses (9
  special/ceremony hulls). Current eligible count is 421.
- Standard: mild high-usage preference:
  `1 + 2.2 * log1p(recent)/log1p(max)`.
- Abyss: mild low-usage preference:
  `1 + 1.8 * (1 - normalized)`.
- Weights are expanded ×10, so the high/low difference is roughly 3x, not extreme.
- Pools: `killShipPool` (unique), `normalShipPool`, `abyssKillShipPool`.
- Deterministic pick: sorted pool + `cyrb53(date + dataVersion)`.

## KB selection

- zKill kill reports before **2012-05-22** do not exist; never select them.
- There is no archive mode; the daily target is always today's UTC puzzle.
- Generate a deterministic weighted hull candidate order from the mode pool. The
  Standard and Abyss seeds include the mode, so the two variants are independent.
  Timed mode adds its own suffix and follows the current daily/free mode.
- Request **page 1 only** for each hull in order. Skip the hull when no usable
  record remains.
- Remove entries whose `killmail_time` is on the **current UTC calendar date**
  (00:00–24:00 UTC), as well as pre-2012 entries. This keeps the pool stable
  during the day.
- Shuffle the remaining records with the daily seed plus a mild recency weight:
  newer page-1 records are somewhat more likely to appear first, but the order
  stays meaningfully random.
- The first shuffled record is the **baseline**. Traverse the same shuffled list
  and use the first non-empty record as the **fallback**. If the baseline is
  non-empty, baseline and fallback are the same record.
- A hull is usable only when both baseline and fallback exist. If either is
  missing, continue with the next hull.
- Empty setting on: use the baseline. Empty setting off: use the fallback.
- Empty means no modules, rigs, subsystems, drones or launched fighters with
  quantity > 0. Cargo, spare fighter-bay contents and zero-quantity entries do not
  count. Free-mode random/direct targets follow the same setting.
- If every hull is exhausted without a baseline/fallback pair, show the
  localized no-target screen with a Free mode entry. Never fall back to the
  static kill pool or SDE-only dossier.
- A page-1 fetch failure aborts the selection rather than silently moving to
  another hull, so a transient API problem cannot give players different targets.
- Page 1 is still live data. Excluding the current UTC date stabilizes normal
  hulls, but extremely high-volume hulls can roll older entries off page 1 during
  the day. Strict cross-player equality still requires a published daily snapshot.

## Reveal rules

- Initial clues: weighted random picks (not a fixed sequence), threshold 9 / max 13 /
  max 7 clues; never fewer than 6 candidate hulls; tagged equipment excluded initially.
- Targeting clues (including sensor strength) are static candidate facts for the
  opening six-hull guard.
- Normal mode misses: equipment budget based on fitted equipment count; low
  weight selected first, high-weight items consume more budget and reveal fewer.
- Abyss misses: `+1/+2/+3/+4/+5` equipment clues, plus one weighted
  non-equipment clue each miss. If equipment is short, the uncovered quota is
  halved (rounded up) into additional weighted non-equipment clues.
- All fitted modules are simulated as online and active, never overheated; cargo,
  fuel and spare fighter-bay modules stay offline.
- Abyss static weights start from base stats (so fitted values do not inflate
  weight), then a clue whose fitted value differs from the **all-V no-modules
  baseline** is multiplied by 0.7. Skill-only changes do not reduce weight; only
  module effects do. `calculateDogmaBaseline` supplies that baseline.
- A guess reveals shared static values; two additions stay mixed (equipment and
  attributes) through the replacement rule.
- Reveal RNG seed: `${date}:${killId || shipId}:${mode}`. Never include the guess
  list in the seed, or earlier reveals could change between refreshes.
- Equipment parsing keys by `module type + slot`; a battery fitted in mid and also
  carried in cargo must render as two lines with their own quantities.
- Fighter tubes (158..161) are `fighter`; flag 155 is `fighterBay` and flag 133 is
  `fuelBay`. Only category-87 fighters stay in fighter slots; spare modules,
  charges and scripts there are cargo.
- Standard mode always includes structure resists in the opening clues and gives
  them weight 0 because every hull has the same base structure resists.
- Abyss resistance clues follow the fitted resist gear, not only the base hull
  profile. No resist gear, or only a plain/T1/T2 damage control, caps the clue
  low because calculated values are shared; faction+ damage controls and any
  resistance module floor the clue to at least that module's weight; Assault
  Damage Controls raise it sharply (structure at least 9.5, shield/armor at
  least 8.8); non-uniform structure resists (abyssal weather) reach 9.8.
- Faction+ damage controls and resistance modules receive an 8.2 equipment
  weight floor; their resistance clue cannot weigh less than the module.
- Sensor strength is one clue. It displays only the sensor type(s) with a
  non-zero value: normally one, in the owning race's colour; two special shuttles
  have all four equal. Shield recharge time is a static SDE clue. In Abyss their
  fitted values come from the dogma engine; shield recharge is stored/displayed
  in seconds.
- Low-slot weapon upgrades are weighted by the weapon family they improve
  (projectile/energy/hybrid/missile/drone/disintegrator/turret); matching fitted
  weapons raise weight from 5.8 to at least 7.4.
- Limited modules get a scarcity bonus from how many catalog hulls their
  `fitRestrictions` cover: fewer compatible hulls = higher weight.
- All fitted modules on Corvettes (group 237) and Zephyr (group 1022) are treated
  as limited and weighted accordingly, because those hulls carry built-in gear.
- Fighters are `limited` and weigh 10; Excavator/Pluto/special mining drones are
  `unique` and weigh 10. Jump fuel weighs 10.
- Rigs weigh at least 8.5; large/capital rigs reach 10.
- All equipment weights are clamped to 1..10, matching the x/10 UI.
- Equipment size adds weight: Capital/XL +7, Large +2.2, Medium +0.8.
- Ammo inherits the strongest real weapon restriction for weight, but never
  displays a limited/unique/officer/abyssal marker. Weapon detection uses SDE
  `chargeGroup*` dogma attributes, so utility high slots (Bastion, Command Burst)
  do not contaminate ammo tags.
- Multiple equipment markers are supported: limited, unique, officer (meta 5),
  abyssal (meta 15), and cargo-only PLEX easter egg. Each marker has a localized
  `title`/`aria-label` hint.
- Abyss fallback is always a same-group/same-size representative of the abyssal
  module itself. It first picks the highest **meta group** present in the same
  slot, then the candidate with the closest **meta level** (attribute 633).
  - Single hierarchy: officer → deadspace → faction → T2 → highMeta → T1.
  - Never use a tier higher than the slot's highest meta group; walk that one
    order from the slot tier downward.
  - Within the first tier that has candidates, pick the closest meta level.
  - Example: X-Type armor hardener meta 16 in low → X-Type repairer meta 16.
  - Example: Entropic Radiation Sink has no deadspace variant → faction Veles
    (meta 8), not officer Zorya.
  - The manifest stores all same-group candidates per tier, not only one.
  - It must never substitute an unrelated module line (e.g. armor repairer into ballistic).
- Before `calculateDogmaFit`, abyssal fit items are cloned and their type IDs are
  replaced by those tier representatives (cargo untouched). The UI/equipment
  clues keep the original abyssal IDs; only the attribute calculation is substituted.
- Official SDE de/ru item names are almost entirely English (5,370+ of 5,378);
  this is upstream behavior, not a locale fallback bug. Displaying English there
  matches the EVE client and EVE Ref. Only zh/es/fr/ja/ko have broad SDE names.

## Stats and reset

- Stats live in `fitdle:v1:stats`, independent of `dataVersion` and builds.
- Daily plays and kills are per gameplay mode: Standard, Abyss, Timed.
- A play is counted on the first guess, or on starting a Timed run.
- Free runs never affect stats.
- Streak is measured in consecutive successful days. Any gameplay win counts
  that day once; a missed day or a day with no win resets it.
- Legacy numeric totals are migrated to `legacyPlayed`/`legacyWins` and remain
  visible.
- Reset progress uses a five-second press with a left-to-right red fill; there is
  no confirmation dialog and no duration text in the button label.

## Data version

`RULESET_VERSION` + SDE stamp + ship attrs + module count + fallback KB IDs +
usage weights + weighted pool sizes feed `dataVersion`.

- Same SDE + same weights → stable version; no artificial progress reset.
- SDE change, `build:killpool`, or `build:weights` changes `dataVersion` and
  invalidates the current unfinished puzzle only; stats/streak are a separate
  localStorage key.
- Bump `RULESET_VERSION` for reveal/rules/scoring changes.

## Version bump

`.githooks/pre-commit` calls `scripts/bump-version.mjs`.

- The hook defaults to a patch, but ordinary changes should be committed with
  `--no-verify` or `VERSION_BUMP=none` so no version bump occurs.

  `git commit --no-verify`. On a normal Git install the hook works automatically.

## Runtime URLs and storage

- `?rule=abyss` selects Abyss; `?rule=timed` selects Timed; `?rule=standard`,
  an absent rule, or any unknown value selects Standard.
- `?lang=<code>` is accepted only as a legacy input: the value is stored in
  `fitdle:v1:lang` and removed from the URL. Language is never shown in the app URL.
- `?kb=<opaque-token>` opens Free mode for that killmail; legacy numeric IDs are
  accepted and rewritten to tokens. `?free=1` selects a loose-random target.
- Legacy `?mode=abyss`, `?mode=timed`, `?timer=1` and `?timed=1` are accepted
  and canonicalized to `rule`.
- Standard omits `rule` from app and share URLs.
- Standard, Abyss and Timed are peer gameplay modes. Timed is not combined
  with Abyss; its target source follows the selected Daily or Free mode.
- `?d=` is removed/ignored; it is stripped from legacy URLs and never used for selection.
- Puzzle state: `fitdle:v1:state:<date>:<mode>` (Timed uses `<mode>:timed`).
- Stats: `fitdle:v1:stats`; language: `fitdle:v1:lang`; font:
  `fitdle:v1:font`; font size: `fitdle:v1:font-size`; ESI type-name cache:
  `fitdle:v1:typeNames:<locale>`; empty-hull setting: `fitdle:v1:allowEmptyKb`.
- Storage is origin-local; changing domain changes stats and saved language.

## Sharing

- Non-free share URL: `share/{1..6|lost}/{lang}.html?kb=...` with optional `rule=abyss`/`rule=timed`
  (no `d`, `mode`, `timer` or `lang` query; the path locale controls preview
  language and is stored locally).
- Free share URL: `share/free/{lang}.html?kb=...` with optional `rule=abyss`/`rule=timed`.
  The preview redirects to the app without forcing a language.
- Timed share URL: `share/timed/{lang}.html?t=<seconds>&kb=...&rule=timed`.
- Legacy `share/{score}.html` pages remain for old links.
- Opening a `kb` link compares its killmail with the current Daily target for the
  selected gameplay mode. On a match it enters Daily (restoring completed
  progress); otherwise it stays in Free mode.
- Static pages are generated per locale by `build-dist`; metadata is localized and
  contains only score/attempts, never the answer. The page stores its path locale
  locally before redirecting.
- OG images: `assets/share/og-{1..6|lost}-{locale}.png`, 1200×630, localized
  headline/tagline/score, no target or killmail data. `1` uses a cyan
  one-shot/burst card; `lost` uses an amber broken-radar card.
- Regenerate with `python scripts/generate-share-images.py` (Pillow).
- `og:image` is score- and locale-specific, absolute using `SITE_URL` or CI
  `CI_PAGES_URL`. Local builds may read `.cache/local.env` (ignored by Git and CI);
  never commit the local domain into build-dist or docs.
- Free kill IDs are stored in URLs as reversible opaque tokens (`freeKillToken`),
  never as raw IDs, so a shared free link does not spoil the killmail.
- Cargo/type names not in SDE refs are fetched from ESI with `language=<locale>`;
  never reuse `extraTypeNames` across locales. Resolved names are cached in
  localStorage per locale (`fitdle:v1:typeNames:<locale>`) to avoid repeat ESI
  traffic. Abyss representative selection itself is entirely local.

## Known limitations

- zKill APIs can rate-limit; a page-1 failure aborts daily selection and shows
  the retry screen rather than selecting a different target or falling back to SDE.
- Dogma cannot recover the victim's real skills/mutations; simulates all-V and
  active modules.
- Some hulls have no usable zKill page; if every hull is exhausted, the daily
  target shows the no-target screen instead of a static fallback.
- Free mode opens `?kb=<token>` directly. `?free=1` or the free-mode button picks
  a random hull and a random loss from its page 1; this loose random selection is
  intentionally not shared between players. The reveal seed uses the zKill hash or
  killmail time so a shared `?kb=` link reveals identically for everyone.
- Free mode has no persistence or stats.
- Timed is an unscored peer gameplay mode selected with `timer=1`; it starts
  with sealed placeholder dossier blocks. After start it reveals the mode's opening
  clues and releases one weighted clue every 30 seconds; guesses do not release
  clues. Each lock has a 5-second cooldown with a bottom-up fill. The orb shows an
  ASCII spinner and a 30-second ring; if all usable clues are revealed, the next
  scheduled clue fails the run. It has unlimited attempts, a live timer button with
  long-press forfeit, and a timed share page. Its target follows Daily or Free.
- The field manual setting `fitdle:v1:allowEmptyKb` controls whether empty-hull killmails are eligible (default on).
- Font face (one NEW/CLASSIC toggle) and five-step font size are stored in
  `fitdle:v1:font` and `fitdle:v1:font-size`; the default `normal` step is the
  former XL scale. Resistance labels scale with the selected size.
- Stats and language are origin-local; different domains have separate localStorage.
