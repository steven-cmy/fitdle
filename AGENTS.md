# FITDLE — Agent & Maintainer Notes

This file is the engineering/AI handoff. Human-facing introduction and hosting
instructions live in [README.md](README.md).

## Non-negotiable rules

- Never reveal today's target ship, killmail ID, victim name, or answer render in
  tests, logs, commits, screenshots, or chat. Use non-target/public data in screenshots.
- Default to a **patch** version bump whenever code changes are made, unless the
  user explicitly says not to patch. Never bump `minor` or `major` automatically.
- Never create a PR, merge, tag, release, publish Pages, or publish container
  images automatically. Do those only when the user explicitly asks.
- Add `CHANGELOG.md` entries only when preparing an explicitly requested release.
- Do not commit `.cache/`, `dist/`, browser state, or the GitLab token.
- Keep the puzzle deterministic for every player: fixed game-day seed, stable hull /
  page hashes, and completed-month record selection.
- Do not add a backend, account system, or runtime database. The game is static.
- Prefer official SDE/zKill/ESI/image sources. Do not cache images in the repo.
- Do not hard-code deployment domains in authored JS/CSS/HTML. Use `manifest.links`
  or runtime location; share OG images may use build-time `SITE_URL`/`CI_PAGES_URL`.

## Architecture

- Pure static ES modules; no bundler. `dist/` is assembled by
  `scripts/build-dist.mjs`.
- Build-time catalog + runtime zKill/drand. The answer is a victim hull from a
  specific historical killmail; daily selection uses build-time pools and a
  drand time-lock seed.
- `data/manifest.json` is generated by `scripts/build-catalog.mjs`; it contains
  pools, links, data version, SDE build, zKill snapshot, version.
- `data/catalog.json`, `data/refs/*.json`, `data/killpool.json` are generated.
- `dist/` contains authored `js/`, `styles/`, `assets/`, generated `data/`,
  `vendor/dogma-engine/`, `vendor/drand-client/`, and static share pages.
- Build-time configuration lives in ignored `.env` (see `.env.example`), with
  environment variables taking precedence.

### Boot flavor

- Authored file: `assets/boot-flavor.json` (not generated, not in `data/`).
- Normal subtitle pools per locale plus tagged eggs (`en`, `ja`, `zh`).
- Each load picks one normal line; with a 5% chance it picks an egg whose
  `lang` matches the active interface locale.
- The main boot title and the localized scanning status stay fixed.

### Hidden watchlist

- Authored file: `assets/watchlist.json` (not generated, not in `data/`); ships empty.
- Arrays: `characters`, `corporations`, `alliances`; numeric IDs or numeric strings.
- When the current victim matches any watched character/corporation/alliance ID,
  every revealed victim avatar gets an animated rainbow glow.
- Do not expose the list or its match state in the UI, metadata, share pages, or
  any public text. The effect appears only after the puzzle is revealed.

### Multiplayer

- `multiplayer.html` + `js/mp/*` are a statically hosted room shell. Signaling uses
  the vendored PeerJS client and the public PeerJS cloud; game data uses WebRTC
  DataChannels. There is no authored backend, account system or runtime database.
- Room codes and optional passwords are host-owned. Player names are required and
  unique per room. Guests may join mid-round as spectators and become active next
  round.
- Race rooms reuse the entire single-player puzzle in an iframe with
  `?kb=...&mp=1`; each client fetches the same real killmail. Standard/Abyss score
  by finish order; Timed uses the same rank table and ends by rounds.
- Dealer rooms keep the answer and full clue set on the dealer client. Only
  `clue` messages pass through the host relay; the answer is revealed at
  settlement. There is no static target fallback: repeated zKill failures skip
  the dealer/player, and all failures show an error.
- Dealer scoring: published clue weight goes to the dealer; each correct player's
  unpublished-weight snapshot at their solve is split by the final correct count.
  Scores are independent awards, not a conserved pool.
- No TURN relay: some NAT/firewall pairs cannot connect. Host tabs must stay open;
  there is no reconnect or host migration.
- The multiplayer shell never writes daily stats, share URLs, daily state or
  streaks. It reuses `fitdle:v1:lang`, `fitdle:v1:font` and
  `fitdle:v1:font-size`; all scores live in memory.

### Main modules

- `js/main.js` — boot, target/KB resolution, rendering, radar, free mode,
  language/mode, sharing, modals, footer.
- `js/game.js` — date/downtime helpers, deterministic target picking, state,
  stats, share URL, result grid.
- `js/clues.js` — SDE clue construction, profile matching, equipment weights,
  abyss base-value weights, module size weighting.
- `js/reveal.js` — immutable per-answer reveal plan, weighted category queues,
  Standard equipment/cargo budgets, Abyss quotas/transfer, Timed release quota,
  and guess matching.
- `js/i18n.js` — 8 locales, legal copy, manual copy; all zh variants → `zh`.
- `js/dogma.js` / `vendor/dogma-engine` — abyss all-V simulation.
- `multiplayer.html` / `js/mp/*` — statically hosted multiplayer shell, PeerJS room
  signaling, race overlay and dealer room; no authored backend.
- `scripts/*` — SDE, killpool, ship weights, dogma, catalog, dist, version hooks.
- Ship bonus extraction preserves every localized SDE bonus line; never truncate
  to a fixed count. Some hulls exceed four bonuses (Naga Navy Issue has five,
  including its max-velocity bonus; Python has many role bonuses).

## Data flow

1. `prepare:sde` downloads/extracts the official JSONL SDE and normalizes it.
2. `build:killpool` builds a small offline fallback pool from zKill global losses
   and stores zKill's server `Date` as `serverDate`.
3. `build:weights` fetches zKill `stats/shipTypeID/{id}/kills/` for all SDE hulls
   and stores recent/all ship-loss counts in `.cache/ship-weights.json`.
   zKill's `rankings.recent` bucket is a 90-day window; the internal `losses30`
   clue key is legacy, and the UI must label it as 90 days.
4. `build` reads normalized SDE + weights + killpool and writes `data/` and
   `dist/`. It also emits a compact `data/module-fallback.json` from
   `typeDogma` for the six attributes used by the abyss fallback simulator, so
   that fallback never calls ESI at runtime.
5. Runtime: read the authenticated game day, fetch the configured drand round,
   walk the deterministic hull queue, sample a recency-weighted target time, then
   select a killmail from the scanned ship-loss pages. No daily build is required.

## Target selection

- Eligibility: all SDE hulls except those with zero all-time zKill losses (9
  special/ceremony hulls). Current eligible count is 421.
- Standard: mild high-usage preference:
  `1 + 2.2 * log1p(recent)/log1p(max)`.
- Abyss: mild low-usage preference:
  `1 + 1.8 * (1 - normalized)`.
- Pools are fixed at build time: `normalShipPool`, `abyssKillShipPool`. Repeated
  IDs are integer weights.
- Daily seed: `cyrb53('fitdle:v4:' + gameDay + ':' + drandRandomness)`.
  `dataVersion` is never part of the daily seed.
- Ship: weighted rendezvous order over the mode pool. Each unique ship keeps its
  best copy score; ships are sorted by score with numeric ship ID as the tie-break.
  The first item equals the previous single-ship pick, and later items are the
  deterministic fallback queue. No floats, array order or usage stats are consulted.
- Timed uses its own seed suffix and follows the selected Daily/Free source.
- The target continues to rotate every game day even if the site is not rebuilt;
  SDE and weight changes only apply after a rebuild.

## KB selection

- The game day boundary is build-configurable (`FITDLE_GAME_DAY_START_UTC`);
  default `11:00` UTC.
- Daily target times are sampled from `FITDLE_KB_SELECTION_START_DATE` to the last
  day of the most recent complete month. The sample uses a truncated exponential
  recency distribution with `FITDLE_KB_RECENCY_HALF_LIFE_DAYS`.
- Ships come from one deterministic weighted queue over the full mode pool, seeded
  by the daily drand seed. Only a ship with no usable kill advances to the next
  queue entry.
- Ship loss pages use `/api/losses/shipTypeID/{id}/page/{page}/`; these pages span
  months, so low-volume ships do not produce empty-month requests.
- Page 1 is the latest 200 losses. A page shorter than 200 is the whole history.
  A full page is followed by page 2, 3, ... until the page covers the sampled
  target time, the history ends, or `FITDLE_KB_MAX_SCAN_PAGES` is reached.
- The selected page is filtered by `victim.ship_type_id`, the KB lower bound, the
  complete-month end, and `allowEmptyKb`. The closest kill to the sampled target
  time wins; equal times use a deterministic hash tie-break.
- If the scan cap is reached before the target time, no extra page is requested;
  all already-loaded pages are combined and one kill is chosen with a deterministic
  recency-weighted draw.
- Every ship page is cached locally for 10 minutes, keyed by ship ID and page.
  Failures are not cached. A page 100 scan is the absolute API limit.
- `FITDLE_KB_SELECTION_START_DATE` is a global lower bound for all modes.
  Explicit `?kb=` links bypass it.
- A network/API failure aborts selection; an empty page advances to the next ship.
  Never use the static kill pool, SDE-only dossier, local clock, another day or
  another ship.
- If every queued ship has no candidate, show the localized NO TARGET screen with
  Free mode. Free random targets respect the KB lower bound; explicit `kb` links
  do not.
- There is no archive mode; historical-day consistency is intentionally not
  supported. Only the current game day is synchronized.

## Reveal rules

- Every answer builds one immutable `revealPlan` at `buildAnswerData()` time:
  opening queue plus per-category queues. Queue order is a weighted random
  permutation (low weights more likely early, never a strict weight sort).
- Queue seeds use the daily drand seed for Daily and the stable KB seed for Free,
  then add mode, timed/standard and queue name. Guesses are never part of a seed.
- Opening: budget 9, max weight 13, min 3 / max 7 clues, candidate floor 6; no
  cargo and no bonus in Standard opening, no tagged equipment, one identity and
  one equipment.
- Standard only: guesses reveal shared static values. Bonus clues are never
  proactively revealed; they match only on the same `termKey`
  (`section|normalizeBonusKey(text.en)`), regardless of numeric value/unit. All
  target bonuses sharing that term are revealed.
- Standard misses: equipment queue consumes its weight budget
  (`base + floor(equipmentCount / divisor)`, capped); cargo queue consumes its own
  independent weight budget. Guessed/already-revealed clues skip without cost.
- Abyss: no guess matching. Equipment queue gets `miss` per miss; other queue gets
  `1 + ceil(shortfall / 2)`; cargo gets `max(1, ceil(cargoCount / divisor))`.
  Equipment shortfall transfers to the other queue; cargo/other exhaustion does
  not invent new transfers.
- Timed: one mixed queue, no guess matching; each release consumes the original
  `1, 1, 2, 2, 3, 3...` quota. Opening uses the same opening queue.
- Reveal growth must be monotonic: later rounds only append; a previously shown
  clue never disappears.
- All fitted modules are simulated as online and active, never overheated; cargo,
  fuel and spare fighter-bay modules stay offline.
- Abyss static weights start from base stats (so fitted values do not inflate
  weight), then a clue whose fitted value differs from the **all-V no-modules
  baseline** is multiplied by 0.7. Skill-only changes do not reduce weight; only
  module effects do. `calculateDogmaBaseline` supplies that baseline.
- Equipment parsing keys by `module type + slot`; a battery fitted in mid and also
  carried in cargo must render as two lines with their own quantities.
- Fighter tubes (158..161) are `fighter`; flag 155 is `fighterBay` and flag 133 is
  `fuelBay`. Only category-87 fighters stay in fighter slots; spare modules,
  charges and scripts there are cargo.
- Standard mode always includes structure resists in the opening clues and gives
  them weight 0 because every hull has the same base structure resists.
- Abyss resistance clues follow the fitted resist gear, not only the base hull
  profile. No resist gear, or only a plain/T1/T2 damage control, caps the clue
  low because calculated values are shared; faction+ damage controls and any
  resistance module floor the clue to at least that module's weight; Assault
  Damage Controls raise it sharply (structure at least 9.5, shield/armor at
  least 8.8); non-uniform structure resists (abyssal weather) reach 9.8.
- Faction+ damage controls and resistance modules receive an 8.2 equipment
  weight floor; their resistance clue cannot weigh less than the module.
- Sensor strength is one clue. It displays only the sensor type(s) with a
  non-zero value: normally one, in the owning race's colour; two special shuttles
  have all four equal. Shield recharge time is a static SDE clue. In Abyss their
  fitted values come from the dogma engine; shield recharge is stored/displayed
  in seconds. Drone bay/bandwidth zero always renders as `0`, not a “No drone
  bay” label.
- Low-slot weapon upgrades are weighted by the weapon family they improve
  (projectile/energy/hybrid/missile/drone/disintegrator/turret); matching fitted
  weapons raise weight from 5.8 to at least 7.4.
- Limited modules get a scarcity bonus from how many catalog hulls their
  `fitRestrictions` cover: fewer compatible hulls = higher weight.
- All fitted modules on Corvettes (group 237) and Zephyr (group 1022) are treated
  as limited and weighted accordingly, because those hulls carry built-in gear.
- Fighters are `limited` and weigh 10; Excavator/Pluto/special mining drones are
  `unique` and weigh 10. Jump fuel weighs 10.
- Rigs weigh at least 8.5; large/capital rigs reach 10.
- All equipment weights are clamped to 1..10, matching the x/10 UI.
- Equipment size adds weight: Capital/XL +7, Large +2.2, Medium +0.8.
- Ship bonuses use structured SDE entries: section (role/types), skill type ID,
  importance, numeric bonus, unit ID, localized text, canonical term key, and
  exact term+value key. Never identify a bonus by array index or `importance`
  alone. Rebuild these keys from raw SDE whenever the SDE changes.
- Bonus term identity is section + normalized English text. Exact-value identity
  adds the numeric bonus and unit. More ships sharing a term lowers weight; if
  the value is shared too, lower it further. Distinct values add weight by their
  normalized spread. A unique term is weight 10 and tagged `unique` like
  equipment. Role bonuses are always `limited`; skill bonuses that target a
  race/class are also `limited`. All `limited` bonuses get a weight increase,
  and role bonuses have a higher floor.
- Equipment restriction markers describe the SDE restriction shape, not hull
  count: one `shipGroups` entry or one `shipTypes` entry → `unique`; multiple
  groups/types → `limited`; no restriction → no marker. A unique equipment clue
  weighs 10; limited clues use breadth scarcity.
- Bonus `showinfo` module links carry `links` IDs into the catalog. A bonus
  inherits its linked equipment's marker: one restriction group/type makes the
  bonus `unique` and weight 10, multiple groups/types make it `limited`, and
  unrestricted equipment contributes no equipment-derived marker. Limited
  equipment and its bonus use the same breadth-based rarity weight, so rarer
  restrictions raise both. Assault Damage Control has two groups and is limited;
  Bastion modules have one Marauder group and are unique. Mining-laser/Strip
  Miner bonuses use the same range rule.
- Module metadata includes `requiredSkills`. A bonus linked to a skill affects
  every fitted module whose required skills include it; a bonus linked to a
  module affects that module and its module group. Affected fitted equipment and
  cargo clues are raised to at least the bonus weight, and high-slot/cargo
  ammunition then inherits the boosted weapon weight.
- Module metadata includes `power`/`cpu` and ships include `rigSize`. A fitted
  module's base PG/CPU requirement infers the smallest hull bracket where at
  least half the ships can fit it; medium/large/capital fits receive a size-based
  weight floor. Cargo spare modules are excluded from this inference, while
  cargo charges/scripts inherit the fitted weapon's weight.
- Non-equipment attribute weights use human-discriminable buckets instead of
  exact-value uniqueness: relative/log buckets for mass, speed, signature, HP,
  recharge, capacitor, cargo, range, scan resolution, PG/CPU/calibration,
  absolute buckets for align/warp, exact buckets for slots/hardpoints/locks,
  quantized profiles for resists and sensor strength. Adjacent scalar buckets
  count as the same human-visible range; this prevents tiny differences from
  producing overweight clues. A small bracket-frequency bonus is applied only to
  the class-varying attributes.
- Standard defense clues use a wider value-matching range than Abyss: shield,
  armor and structure HP use a four-times range, while shield recharge and the
  resist layers use twice the base range. This keeps common defensive profiles
  from producing overweight clues.
- Standard never puts bonus clues in its opening or proactive queues; they are
  matching-only. Abyss may put bonus clues in its other queue. Bonus clues do not
  narrow the static candidate set by themselves.
- Debrief bonuses are grouped by skill/class with role bonuses in a separate
  group, using SDE text and bold numeric values. Bonus numeric values use the
  fixed light-blue `#c3e9ff` in every mode/theme, not the theme accent. Skill and
  role group headings use the fixed teal `#4c8cb0`. Bonus limited/unique metadata
  participates in weight calculation but is not shown as a visible badge. In the
  dossier traits section, bonus rows have no "Hull bonus X" prefix.
- Ammo inherits the strongest real weapon restriction for weight, but never
  displays a limited/unique/officer/abyssal marker. Weapon detection uses SDE
  `chargeGroup*` dogma attributes, so utility high slots (Bastion, Command Burst)
  do not contaminate ammo tags.
- Multiple equipment markers are supported: limited, unique, officer (meta 5),
  abyssal (meta 15), and cargo-only PLEX easter egg. Each marker has a localized
  `title`/`aria-label` hint.
- Abyss fallback is always a same-group/same-size representative of the abyssal
  module itself. It first picks the highest **meta group** present in the same
  slot, then the candidate with the closest **meta level** (attribute 633).
  - Single hierarchy: officer → deadspace → faction → T2 → highMeta → T1.
  - Never use a tier higher than the slot's highest meta group; walk that one
    order from the slot tier downward.
  - Within the first tier that has candidates, pick the closest meta level.
  - Example: X-Type armor hardener meta 16 in low → X-Type repairer meta 16.
  - Example: Entropic Radiation Sink has no deadspace variant → faction Veles
    (meta 8), not officer Zorya.
  - The manifest stores all same-group candidates per tier, not only one.
  - It must never substitute an unrelated module line (e.g. armor repairer into ballistic).
- Before `calculateDogmaFit`, abyssal fit items are cloned and their type IDs are
  replaced by those tier representatives (cargo untouched). The UI/equipment
  clues keep the original abyssal IDs; only the attribute calculation is substituted.
- Official SDE de/ru item names are almost entirely English (5,370+ of 5,378);
  this is upstream behavior, not a locale fallback bug. Displaying English there
  matches the EVE client and EVE Ref. Only zh/es/fr/ja/ko have broad SDE names.

## Runtime API caching

- The economy/`ZKILLBOARD` category uses the real target kill value plus cached
  ship-level zKill statistics (90-day losses, usage rank, danger index) when the
  stats request succeeds. No placeholder "data missing" rows are rendered.
- zKill killID responses are cached for 1 hour, keyed by kill ID.
- Ship loss pages are cached per ship/page for 10 minutes. Ship-level zKill stats
  use the same 10-minute bucket. killID responses are cached for 1 hour. Free
  random ship pages use the same 10-minute window.
- The local zKill cache keeps up to 64 entries so a capped page scan does not
  evict its own pages immediately.
- Failed zKill requests retry up to three times; 429/5xx honor `Retry-After` when
  present.
- Daily failure screens are reason-specific: authoritative time, drand beacon,
  zKillboard, or no eligible killmail. The heading is lore copy; the smaller
  `fatal-code`/body carry the actual error. ESI auxiliary-name failures show a
  non-blocking ESI warning instead of blocking the puzzle. Unspecified failures
  use the generic daily-unavailable screen.
- Safe debug logging goes to the browser console for fatal, zKill, drand, time,
  and ESI failures. Public KB/ESI request paths and statuses may be logged.
  Never log client-local state, tokens/nonces, full query URLs, localStorage
  contents, or browser/device information.
- drand rounds are fetched from the official relays and verified by the vendored
  `drand-client`; no alternate beacon chain is used.
- ESI requests append the documented `user_agent` query parameter. Static type
  endpoints use browser caching (`cache: default`), and character/corporation/
  alliance names have a 6-hour localStorage cache.
- The abyss fallback simulator uses `data/module-fallback.json` from the build;
  it never calls ESI for module details. zKill browser requests cannot set a
  custom User-Agent or CORS-safe X-User-Agent, so build scripts carry the
  descriptive User-Agent instead.

## Stats and reset

- Stats live in `fitdle:v1:stats`, independent of `dataVersion` and builds.
- Daily plays and kills are per gameplay mode: Standard, Abyss, Timed.
- A play is counted on the first guess, or on starting a Timed run.
- Free runs never affect stats.
- Streak is measured in consecutive successful days. Any gameplay win counts
  that day once; a missed day or a day with no win resets it.
- Legacy numeric totals are ignored: do not migrate or display `legacyPlayed` /
  `legacyWins` from older builds.
- Reset progress uses a five-second press with a left-to-right red fill; there is
  no confirmation dialog and no duration text in the button label.

## Data version

`RULESET_VERSION` + SDE stamp + ship attrs + module count + fallback KB IDs +
usage weights + weighted pool sizes feed `dataVersion`.

- Same SDE + same weights → stable version; no artificial progress reset.
- SDE/weights/pool changes feed `dataVersion`; the unfinished daily state is also
  keyed by the saved drand seed and answer killmail, so a same-target rebuild does
  not reset progress. Stats/streak remain a separate localStorage key.
- Bump `RULESET_VERSION` for reveal/rules/scoring changes.

## Runtime URLs and storage

- `?rule=abyss` selects Abyss; `?rule=timed` selects Timed; `?rule=standard`,
  an absent rule, or any unknown value selects Standard.
- `?lang=<code>` is accepted only as a legacy input: the value is stored in
  `fitdle:v1:lang` and removed from the URL. Language is never shown in the app URL.
- `?kb=<opaque-token>` opens Free mode for that killmail; legacy numeric IDs are
  accepted and rewritten to tokens. The random free flow uses a temporary
  `?n=<nonce>` query that is removed after the target loads. Legacy `?free=1`
  still opens a loose-random target but is neutral for streaks.
- Legacy `?mode=abyss`, `?mode=timed`, `?timer=1` and `?timed=1` are accepted
  and canonicalized to `rule`.
- Standard omits `rule` from app and share URLs.
- Standard, Abyss and Timed are peer gameplay modes. Timed is not combined
  with Abyss; its target source follows the selected Daily or Free mode.
- `?d=` is removed/ignored; it is stripped from legacy URLs and never used for selection.
- Puzzle state: `fitdle:v1:state:<date>:<mode>` (Timed uses `<mode>:timed`).
- Stats: `fitdle:v1:stats`; free-mode streaks: `fitdle:v1:free-streak`;
  free-mode one-time nonce: `fitdle:v1:free-intent` (sessionStorage); language:
  `fitdle:v1:lang`; font: `fitdle:v1:font`; font size: `fitdle:v1:font-size`;
  ESI type-name cache: `fitdle:v1:typeNames:<locale>`; zKill response cache:
  `fitdle:v1:zkill:*`; entity-name cache: `fitdle:v1:entity-names`; empty-hull
  setting: `fitdle:v1:allowEmptyKb`.
- Storage is origin-local; changing domain changes stats and saved language.

## Sharing

- Non-free share URL: `share/{1..6|lost}/{lang}.html` with optional `rule=abyss`/`rule=timed`
  (no `kb`, `d`, `mode`, `timer` or `lang` query; the path locale controls preview
  language and is stored locally). Daily shares must not carry a reversible kill token.
- Free share URL: `share/free/{lang}.html?kb=...` with optional `rule=abyss`/`rule=timed`.
  The preview redirects to the app without forcing a language.
- Timed share URL: `share/timed/{lang}.html?t=<seconds>&rule=timed`; Free Timed
  additionally carries `kb=...`.
- Legacy `share/{score}.html` pages remain for old links.
- Opening a `kb` link compares its killmail with the current Daily target for the
  selected gameplay mode. On a match it enters Daily (restoring completed
  progress); otherwise it stays in Free mode.
- Static pages are generated per locale by `build-dist`; metadata is localized and
  contains only score/attempts, never the answer. The page stores its path locale
  locally before redirecting.
- OG images: `assets/share/og-{1..6|lost}-{locale}.png`, 1200×630, localized
  headline/tagline/score, no target or killmail data. `1` uses a cyan
  one-shot/burst card; `lost` uses an amber broken-radar card.
- Regenerate with `python scripts/generate-share-images.py` (Pillow).
- `og:image` is score- and locale-specific, absolute using `SITE_URL` or CI
  `CI_PAGES_URL`. Local builds may read `.cache/local.env` (ignored by Git and CI);
  never commit the local domain into build-dist or docs.
- Free kill IDs are stored in URLs as reversible opaque tokens (`freeKillToken`),
  never as raw IDs, so a shared free link does not spoil the killmail.
- Cargo/type names not in SDE refs are fetched from ESI with `language=<locale>`;
  never reuse `extraTypeNames` across locales. Resolved names are cached in
  localStorage per locale (`fitdle:v1:typeNames:<locale>`) to avoid repeat ESI
  traffic. Abyss representative selection itself is entirely local.

## Manual and legal

- Manual left column is split into Mode descriptions (Daily, Free) and Gameplay
  descriptions (General, Standard, Abyss, Timed).
- Dossier layout: groups are balanced across two dynamic columns; equipment/cargo
  are not pinned to a column. The dossier header shows only the title; it has no
  subtitle sentence. Cargo capacity is the first row of the cargo group
  and keeps a labeled placeholder while hidden, including zero-cargo hulls.
- Newly revealed clues that are outside the viewport show a fixed edge arrow
  until the player scrolls them into view; clicking the arrow scrolls to the
  nearest unseen clue. Initial reveals also seed the unseen set when a fresh
  puzzle is opened with no guesses yet.
- A valid killmail whose victim hull is not in the catalog (for example a
  structure or container kill) shows the localized "signal unclassified" lore
  screen with a back button. It must not silently fall back to the daily target.
- The cargo group counter counts revealed cargo items only, excluding cargo
  capacity. It shows `revealed / ?` until every cargo item is revealed, then
  `X / X`; an empty cargo hold shows `0 / 0`.
- When a dossier equipment/cargo group has revealed rows followed by hidden
  rows, insert the `sealed-divider` line before the sealed row.
- After the answer is revealed, the radar answer render fills its circular stage
  with `object-fit: cover` at natural scale; do not add an extra zoom transform.
- Mass shows a fully written, non-abbreviated number by default in tonnes,
  using spaces as thousands separators and `t` as the unit. Clicking the mass
  row toggles between tonnes and kg; clicking again returns to tonnes. The kg
  state keeps the `kg` unit label. The mass row has no hover background effect.
- Manual shared rules are in `help.sharedRules` and appear under General.
  User-facing manual copy must stay abstract: describe the mode experience and
  guess behavior only; never expose queue names, budgets, weights, counts,
  thresholds, transfer formulas, or seed details.
- Mode sections must contain only mode-specific rules.
- Do not restore the removed sentence about identical UTC target/language in
  step 04.
- Legal copy follows the ximicon.space CCP notice pattern, localized legally,
  with Fenris Creations (formerly CCP hf.) and the deployed site URL as the site
  subject. Never embed the GitLab repository URL in the legal copy.

## CI / deployment

- `.gitlab-ci.yml`: `sde:check`, `build`, `publish:builder`, `release`, `pages`.
- The one-shot builder image is independent of the application version. On a
  `main` push that changes `docker/BUILDER_VERSION`, `publish:builder` builds
  `Dockerfile.oneshot` with Kaniko and pushes
  `<CI_REGISTRY_IMAGE>/builder:<builder-version>` and `:latest`. Changing only
  the application/package version does not publish a new builder image.
- `release` depends only on `build`, not on `publish:builder`; application
  releases continue even when builder code did not change.
- When changing `Dockerfile.oneshot` or the builder entrypoint, bump
  `docker/BUILDER_VERSION` so a new image is published.
- `publish:builder:test` is a manual web/MR pipeline smoke test; it pushes only
  `:test` and is never automatic. It uses the automatic `CI_JOB_TOKEN`; no Docker
  Hub credentials or registry variables are needed.
- On a `main` push that changes `package.json`, after a successful build the
  `release` job creates a `v<version>` tag/release. GitLab's automatic source
  archives are used; no custom source tarball is built.
- `sde:check` compares remote SDE ETag/Last-Modified with deployed
  `data/manifest.json`; writes `.cache/sde-check.env`.
- The build job skips `prepare:sde` when SDE is unchanged and normalized schema
  version 2 is cached; only a schema/SDE change downloads the SDE again.
- Build caches `.cache/normalized.json`, `.cache/killpool.json`,
  `.cache/sde-meta.json`, `.cache/ship-weights.json`.
- The one-shot builder mounts `/cache` separately from `/out`; it checks the
  official SDE before each build and re-downloads it when the cached build is
  stale, refreshes killpool at most once per day, and uses the 7-day weights
  cache unless `FORCE_WEIGHTS=1`. `FORCE_SDE=1` bypasses the check and forces a
  fresh SDE download. Its builder version is independent and currently `1.2.0`.
- If `data/catalog.json` is missing, build first; weights need a catalog.
- Daily scheduled pipeline is disabled: daily selection no longer depends on a
  rebuild. Builds remain manual/web/MR driven. If the GitLab schedule still exists,
  its workflow rule is intentionally absent and it must not be relied on for target
  updates.
- `pages` publishes `dist/` to `public/`.

  https://fitdle-717fa9.gitlab.io/.

## Known limitations

- zKill APIs can rate-limit; a ship-page failure aborts daily selection and shows
  the Daily unavailable screen (with Free mode) rather than selecting a different
  target or falling back to SDE or local time.
- Dogma cannot recover the victim's real skills/mutations; simulates all-V and
  active modules.
- A ship whose sampled target is older than its history, or needs more than
  `FITDLE_KB_MAX_SCAN_PAGES` pages, uses a recency-weighted draw over the pages
  already loaded; if no usable kill exists, the queue advances.
- zKill caps ship pagination at 100 pages. Very high-volume ships cannot expose
  their full history through this API, so older targets may be unreachable.
- The daily seed is only knowable after the configured start + drand grace period.
  Before then the previous game day remains playable; the page does not guess the
  next target.
- Free mode opens `?kb=<token>` directly. The free-mode button/refresh picks a
  random hull and a random loss from its page 1 using a temporary nonce; legacy
  `?free=1` still picks a loose-random target but is neutral for streaks. This
  loose random selection is intentionally not shared between players. The reveal
  seed uses the zKill hash or killmail time so a shared `?kb=` link reveals
  identically for everyone.
- Free mode has no stats and no daily puzzle persistence; only its separate
  per-gameplay streak counters persist.
- Free mode keeps separate Standard/Abyss/Timed streak counters in
  `fitdle:v1:free-streak`. Only a win from the random refresh flow increments the
  current gameplay counter; wins opened from a direct `kb` link or a free share
  link do not increment. The random refresh flow uses a one-time nonce stored in
  `fitdle:v1:free-intent` (sessionStorage) and binds it to the URL; direct
  `kb`/share links and forged `free=1` URLs are neutral. A loss or an abandoned
  active round (page close, refresh, or mode navigation) resets that gameplay
  counter. After a completed round, mode changes or direct `kb`/share links leave
  the streak intact until the next random refresh starts a round. Free debriefs
  replace the daily streak-days stat with the per-gameplay free streak, shown in
  that stat position at the same value size but bold. Counted random refresh
  rounds play increment pop/confetti or reset shake effects; direct `kb`/share
  debriefs show the current counter greyed out with no effects. Victim
  character/corporation/alliance information sits to the right of the confirmed
  ship row on every debrief.
- Timed is a peer gameplay mode selected with `timer=1`; it has no six-attempt
  score, but daily plays and wins are recorded like the other daily modes. It starts
  with sealed placeholder dossier blocks. After start it reveals the mode's opening
  clues and releases a weighted batch every 30 seconds; guesses do not release
  clues. The batch grows every two releases: 1, 1, 2, 2, 3, 3, ... clues. Its
  fitted values are simulated the same way as Abyss. Each lock has a 5-second
  cooldown with a bottom-up fill. If all usable clues are already revealed, the
  next release fails the run; if fewer clues remain than the next batch, all
  remaining clues are released and failure waits until the following release.
  It has unlimited attempts, a live timer button with long-press forfeit, and a
  timed share page. Its target follows Daily or Free.
- The field manual setting `fitdle:v1:allowEmptyKb` controls whether empty-hull killmails are eligible (default on).
- Font face (one NEW/CLASSIC toggle) and five-step font size are stored in
  `fitdle:v1:font` and `fitdle:v1:font-size`; the default `normal` step is the
  former XL scale. Resistance labels scale with the selected size.
- All authored UI text must use `rem`/`em` derived from the root font size; do
  not introduce fixed `px` font sizes for managed text. Free-streak values match
  the neighboring stat values, labels match the neighboring stat labels, and
  their confetti/shake effects scale with the root font size.
- In every debrief, victim character/corporation/alliance information sits to the
  right of the confirmed-ship row. The character name is base-size text, the
  corporation/alliance lines are slightly smaller and show only their names, with
  no organization labels; only the character name text itself is the link target,
  not the full row.
- Stats and language are origin-local; different domains have separate localStorage.
- Multiplayer rooms depend on the public PeerJS cloud for signaling and on zKill for
  targets. There is no TURN relay, so some NAT/firewall pairs fail to connect; the
  host tab must stay open and there is no reconnect or host migration.
- Multiplayer targets are real killmails only. A failed dealer/player request is
  retried and then skipped; if every attempt fails the room shows an error instead
  of falling back to static clues.
- Dealer scoring follows the tentative published/unpublished rule. Publishing every
  clue maximizes the dealer's score while leaving correct players zero unpublished
  weight; early solvers also lock a snapshot that later publications do not reduce.
  This is a balance risk to review after playtesting, not a scoring bug.
- The race room embeds the normal single-player page with `?kb=...&mp=1`; the
  single-player free-mode rules and UI are reused. A random multiplayer target can
  coincide with the current daily target, but no daily target data is fetched or
  labelled by the room.
- Multiplayer scores are in-memory only; they do not affect daily stats, streaks,
  share pages or the field manual.
